# Real-Time Streaming Implementation

## Overview

This implementation adds real-time token streaming capabilities to the EduSmart FastAPI backend using Server-Sent Events (SSE). Tokens are streamed as they are generated by the LLM, providing a responsive user experience.

## Architecture

### Components

1. **LLMClient** (`app/services/llm/llama_cpp_client.py`)
   - Enhanced with streaming methods
   - `generate_stream()`: Synchronous generator using llama.cpp native streaming
   - `generate_stream_async()`: Async wrapper using ThreadPoolExecutor
   - `_mock_stream()`: Mock streaming for testing
   - ThreadPoolExecutor with 4 workers for non-blocking async operations

2. **StreamingService** (`app/services/streaming_service.py`)
   - `StreamEvent`: Dataclass for SSE events with `to_sse()` formatter
   - `StreamEventType`: Enum (TOKEN, METADATA, ERROR, DONE, STATUS)
   - `stream_response()`: Main async generator with error handling and metadata tracking

3. **Streaming Router** (`app/routes/streaming.py`)
   - POST `/api/v1/stream/chat`: SSE endpoint
   - Uses `sse-starlette` EventSourceResponse
   - Accepts prompt and optional generation parameters

## Event Types

### STATUS
Emitted when streaming starts.
```json
{
  "status": "started",
  "request_id": "uuid",
  "timestamp": 1234567890.123
}
```

### TOKEN
Emitted for each generated token.
```json
{
  "token": "word ",
  "partial_text": "accumulated text so far",
  "token_count": 42
}
```

### METADATA
Emitted every 10 tokens with performance metrics.
```json
{
  "token_count": 50,
  "elapsed_seconds": 2.34,
  "tokens_per_second": 21.37
}
```

### DONE
Emitted when generation completes successfully.
```json
{
  "status": "completed",
  "full_response": "complete generated text",
  "total_tokens": 123,
  "elapsed_seconds": 5.67,
  "tokens_per_second": 21.69,
  "request_id": "uuid"
}
```

### ERROR
Emitted if generation fails (preserves partial response).
```json
{
  "status": "error",
  "error": "error message",
  "error_type": "RuntimeError",
  "partial_response": "text generated before error",
  "tokens_generated": 45,
  "elapsed_seconds": 2.1,
  "request_id": "uuid"
}
```

### Frontend Integration

#### Using EventSource API:
```javascript
const eventSource = new EventSource(
  'http://localhost:8000/api/v1/stream/chat',
  {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({
      prompt: 'Explain quantum computing',
      temperature: 0.7,
    }),
  }
);

eventSource.addEventListener('status', (e) => {
  const data = JSON.parse(e.data);
  console.log('Stream started:', data.request_id);
});

eventSource.addEventListener('token', (e) => {
  const data = JSON.parse(e.data);
  // Append token to UI
  appendToken(data.token);
});

eventSource.addEventListener('metadata', (e) => {
  const data = JSON.parse(e.data);
  console.log(`Speed: ${data.tokens_per_second} tok/s`);
});

eventSource.addEventListener('done', (e) => {
  const data = JSON.parse(e.data);
  console.log('Complete:', data.full_response);
  eventSource.close();
});

eventSource.addEventListener('error', (e) => {
  const data = JSON.parse(e.data);
  console.error('Error:', data.error);
  console.log('Partial:', data.partial_response);
  eventSource.close();
});
```

#### Using fetch with ReadableStream:
```javascript
const response = await fetch('http://localhost:8000/api/v1/stream/chat', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({
    prompt: 'Explain machine learning',
  }),
});

const reader = response.body.getReader();
const decoder = new TextDecoder();

while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  
  const chunk = decoder.decode(value);
  const lines = chunk.split('\n\n');
  
  for (const line of lines) {
    if (!line.trim()) continue;
    
    const eventMatch = line.match(/^event: (.+)$/m);
    const dataMatch = line.match(/^data: (.+)$/m);
    
    if (eventMatch && dataMatch) {
      const eventType = eventMatch[1];
      const data = JSON.parse(dataMatch[1]);
      
      handleEvent(eventType, data);
    }
  }
}
```

## Configuration

### Generation Parameters

All parameters are optional and fall back to settings defaults:

- `temperature` (0.0-2.0): Sampling temperature (default: `FINAL_LLM_TEMPERATURE`)
- `top_p` (0.0-1.0): Nucleus sampling (default: `FINAL_LLM_TOP_P`)
- `top_k` (≥1): Top-k sampling (default: None)
- `max_tokens` (≥1): Maximum tokens (default: `FINAL_LLM_MAX_TOKENS`)

### Environment Variables

Streaming uses existing LLM configuration from `app/core/config.py`:

```env
# LLM Mode
LLM_MODE=gpu  # cpu | desktop | gpu

# Final LLM Settings (used for streaming)
FINAL_LLM_CONTEXT_SIZE=4096
FINAL_LLM_THREADS=8
FINAL_LLM_MAX_TOKENS=1024
FINAL_LLM_TEMPERATURE=0.7
FINAL_LLM_TOP_P=0.9

# GPU Settings (when LLM_MODE=gpu)
FINAL_LLM_N_GPU_LAYERS=12
FINAL_LLM_N_BATCH=256
FINAL_LLM_GPU_F16_KV=true

# Mock Mode (for testing)
ENABLE_MOCK_LLM=false
```

## Performance Characteristics

### Streaming Overhead
- ThreadPoolExecutor with 4 workers prevents event loop blocking
- Tokens are yielded immediately as generated
- Metadata updates every 10 tokens minimize overhead
- Typical latency: <50ms per token on CPU, <20ms on GPU

### Resource Usage
- Memory: Minimal overhead (~10MB for executor)
- CPU: Same as non-streaming generation
- Network: Efficient SSE protocol with automatic reconnection

## Error Handling

### Graceful Degradation
- Partial responses preserved on error
- Error events include diagnostic information
- Client can display partial results before failure

### Common Errors
1. **Model not initialized**: Check `ENABLE_MOCK_LLM` and model paths
2. **Context overflow**: Reduce `max_tokens` or prompt length
3. **Connection timeout**: Client should implement reconnection logic

## Troubleshooting

### Streaming not working
1. Check `sse-starlette` is installed: `pip install sse-starlette>=1.6.5`
2. Verify router is registered in `main.py`
3. Check CORS settings allow streaming

### Slow streaming
1. Increase `FINAL_LLM_N_GPU_LAYERS` if using GPU
2. Reduce `FINAL_LLM_N_BATCH` if memory constrained
3. Check CPU/GPU utilization

### Mock mode not streaming
1. Verify `ENABLE_MOCK_LLM=true` in `.env`
2. Check `_mock_stream()` method is being called
3. Ensure delays are appropriate for testing
